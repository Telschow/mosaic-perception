# TASK

Before merging, run `gh issue view <ID> --json labels` for each issue below. An issue labelled `wayfinder:research` is a findings report: do not merge its branch. Push that branch with `git push origin <branch>`, comment on the issue with its link, and leave the issue open.

Merge these branches into the current branch, one at a time:

{{BRANCHES}}

For each: `git merge <branch> --no-edit`. On conflict, read both sides and resolve to keep both intents. Never force-push or rewrite history.

After the last merge, run once:

1. `ruff check src tests scripts`
2. `ruff format --check src tests scripts`
3. `mypy src --ignore-missing-imports`
4. `make benchmark-golden-check` and `make provenance-check`

Do not run the full pytest suite. CI runs it on `main` after the push. Run each check in the foreground and wait for it. Do not start background watchers.

If something fails, fix it and rerun only what failed. Do not type numbers by hand; regenerate artifacts with the Makefile targets.

# PUSH AND PULL REQUEST

Only when every check above passes. Never push to `main`. Never force-push and never rewrite history.

1. `git fetch origin`
2. `git merge origin/main --no-edit`. If this brings in changes, rerun the four checks.
3. Push the current branch: `git push -u origin HEAD`
4. Open a pull request into `main` with `gh pr create --base main --title "<conventional subject>" --body-file <file>`. The body starts with `> *This was generated by AI during Sandcastle.*`, then a short summary per merged branch, then one `Closes #<ID>` line per merged issue.

If the push or `gh pr create` fails, fetch, merge `origin/main` once more and try once more. If it fails again, stop and say so.
